# PassMaster

Симуляция студента, который прогуливает пары и пытается получить максимум удовольствия,
не вылетев

## Правила игры

- В семестре **6 предметов** (`Contracts/Subject.cs`): матан, линал, дискретка,
  программирование, физика, английский.
- У каждого преподавателя есть **одно правило**, выбранное случайно один раз
  и не меняющееся до конца прогона:
  - **Random** — спрашивает с вероятностью 50 % независимо от истории;
  - **AskIfA** — спрашивает сегодня, если вчера спросили предмет `A`;
  - **AskIfXorAB** — спрашивает, если вчера спросили ровно один из предметов `A` и `B`
    (XOR).
- `A` выбирается из всех 6 предметов и может совпадать с собственным предметом
  преподавателя. `B` выбирается из оставшихся 5, поэтому `B != A`.
- В первый день «вчерашний» вектор ответов пуст — все `false`.
- Студент решает, идти на пару или прогулять, **до** того, как станут известны
  сегодняшние ответы преподавателей.

### Удовольствие

| Событие | Эффект |
|---|---|
| Успешный прогул (не спросили) | **+1** |
| Пирожок в конце дня | **+1**, если студента не поймали |
| Прогулял, и его спросили | **вылет**: удовольствие сбрасывается в **0** |

В день вылета пирожок не начисляется, а остальные предметы дня в live-режиме
уже не доигрываются.

### Что знает стратегия

Стратегия получает только read-only историю (`Contracts/IReadOnlyStudentHistory.cs`):

```csharp
bool  Attended(int day, Subject subject);   // приходил ли студент
bool? WasAsked(int day, Subject subject);   // спрашивали ли; null, если прогулял
```

Фактическое удовольствие и факт вылета стратегии **не видны**. Поэтому байесовские
стратегии считают удовольствие математическим ожиданием самостоятельно.

## Два режима работы

### Live-режим (по умолчанию)

Реализован на **Generic Host** (`Microsoft.Extensions.Hosting`).

- первый день играется сразу при запуске;
- каждый следующий — через `--interval` секунд (по умолчанию **5**);
- дни не ограничены: после 100-го идёт 101-й и так далее;
- при вылете приложение **сразу** останавливается (`StopApplication`);
- любую клавишу тоже можно нажать для остановки.

### Batch-режим (`--batch`)

Старый режим лабораторной №1:

- `Constants.Iterations = 1000` семестров по `Constants.DaysCount = 100` дней;
- вылет **не** останавливает прогон: удовольствие обнуляется, игра продолжается;
- в конце печатается среднее удовольствие, среднее число вылетов и максимум.

## Быстрый старт

### Требования

- **.NET SDK 10** (`net10.0`).
- Пакет `Microsoft.Extensions.Hosting` 10.0.12 подтягивается автоматически.

### Запуск из терминала

```powershell
# live-режим, стратегия по умолчанию, день каждые 5 секунд
& "$env:USERPROFILE\.dotnet\dotnet.exe" run

# быстрый интервал, безопасная стратегия
& "$env:USERPROFILE\.dotnet\dotnet.exe" run -- --interval 1 --strategy BayesSafe

# batch: 1000 семестров по 100 дней, фиксированный seed
& "$env:USERPROFILE\.dotnet\dotnet.exe" run -- --batch --seed 12345 --strategy BayesOptimal

# справка
& "$env:USERPROFILE\.dotnet\dotnet.exe" run -- --help
```

Сборка:

```powershell
& "$env:USERPROFILE\.dotnet\dotnet.exe" build PassMaster.csproj -v minimal
```

> Обратите внимание на `--` после `run`: всё, что идёт дальше, передаётся самой программе,
> а не `dotnet`.

## Параметры командной строки

| Параметр | Значение по умолчанию | Описание |
|---|---|---|
| `--strategy <имя>` | `BayesOptimal` | Какую стратегию использовать |
| `--interval <сек>` | `5` | Интервал между днями в live-режиме |
| `--batch` | выключен | Режим лабораторной №1: 1000 прогонов и статистика |
| `--seed <число>` | случайный | Seed для batch-прогона (воспроизводимость) |
| `--help`, `-h` | — | Показать справку |

Поддерживаются обе формы записи: `--strategy BayesSafe` и `--strategy=BayesSafe`.

`--seed` влияет только на batch: при одинаковом seed две стратегии играют
на **одних и тех же** преподавателях, поэтому их можно честно сравнивать.

## Стратегии

| Имя | Среднее удовольствие* | Вылетов* | Идея |
|---|---:|---:|---|
| **BayesOptimal** (по умолчанию) | **345.7** | 1.09 | Байесовская, максимум ожидаемого удовольствия |
| **BayesSafe** | 290.1 | **0.00** | Та же модель, но без риска вообще |
| CautiousScout | 215.4 | 0.00 | 20 дней ходит на всё, потом прогуливает предметы, где ни разу не спросили |
| PrudentStudent | 100.0 | 0.00 | Всегда ходит на все пары (только пирожки) |
| ImprudentStudent | 55.6 | 225.9 | Никогда не ходит |
| RandomSkip | 32.9 | 113.3 | Ходит случайно, 50/50 |

\* 1000 семестров по 100 дней, `--seed 12345`. Значения слегка меняются от seed.

Алиасы: `bayes`/`optimal` → `BayesOptimal`, `safe` → `BayesSafe`,
`cautious` → `CautiousScout`, `prudent`/`alwaysattend` → `PrudentStudent`,
`imprudent`/`neverattend`/`skipall` → `ImprudentStudent`, `random`/`randomskip` → `RandomSkip`.

> **Что выбрать.** `BayesOptimal` — максимум среднего за семестр, но примерно раз
> за семестр студент вылетает. В live-режиме первый вылет завершает игру, поэтому
> для долгой демонстрации лучше `BayesSafe`: он даёт меньше, зато не вылетает никогда.

## Как работает BayesOptimal

Файлы: `Strategy/BayesOptimalStudent.cs` (риск-нейтральная) и
`Strategy/BayesSafeStudent.cs` (строго безопасная). Модель у них общая.

### 1. 37 гипотез на каждый предмет

Скрыты три вещи: правило, предмет `A` и предмет `B`. Это даёт ровно 37
взаимоисключающих гипотез:

| Гипотеза | Количество | Априорная вероятность |
|---|---:|---:|
| `Random` | 1 | 1/3 |
| `AskIfA` | 6 (по одной на каждый `A`) | 1/18 |
| `AskIfXorAB` | 30 (6·5 пар `A != B`) | 1/90 |

Стратегия хранит вероятность каждой гипотезы и после каждого дня, когда студент был
на паре, пересчитывает их по формуле Байеса:

```
P(гипотеза | наблюдение) ∝ P(наблюдение | гипотеза) · P(гипотеза)
```

где наблюдение — «спросили» или «не спросили».

### 2. Вектор `q`

Правило преподавателя зависит от **вчерашнего** вектора «кого спросили» (`q`).
В день 0 он весь `false`. Дальше:

- был на паре → `q[s]` равно фактическому ответу;
- прогулял → `q[s] = false`.

Второе корректно, потому что прогуливаем мы только те предметы, где вероятность
вопроса практически нулевая. Значит, преподаватель действительно не спросил,
и `false` — это факт, а не догадка.

### 3. Решение дня

Для каждого предмета posterior даёт вероятность вопроса `p`. Затем перебираются
все `2^6 = 64` набора прогулов и максимизируется ожидаемое удовольствие после дня:

```
P(никого не спросят) × (P + число прогулов + 1)
```

где `P` — ожидаемое накопленное удовольствие, `+1` — пирожок.

### 4. Почему это оптимально

Пусть накопленное удовольствие равно `P`. Прогул предмета с вероятностью вопроса `p` даёт

```
(1 - p) × (P + 2)      // прогул удался: +1 за прогул и +1 за пирожок
```

против

```
P + 1                  // пошёл на пару: только пирожок
```

Прогул выгоден, когда `p < 1 / (P + 2)`. При `P ≈ 300` это `p < 0.3 %`.
Ценность состояния линейна по `P` (при вылете всё обнуляется, успехи складываются),
поэтому жадный выбор по ожидаемому `P` совпадает с оптимальной многошаговой политикой.

### 5. Предохранитель `MaxAskProbability`

Без ограничения при `P = 0` порог выгодности равен `0.5`, а у необученного
преподавателя `p ≈ 1/6` — чистая жадность рисковала бы почти всем с первого дня.
Это увеличивает одну ожидаемую величину, но ценой большого числа вылетов и потери
информации. Поэтому риск ограничен сверху: прогуливаем предмет, только если
`p <= 0.005`. Эмпирически это дало **лучший** результат (345.7 против 303.0
у неограниченной жадности).

### 6. Почему BayesSafe никогда не вылетает

В `BayesSafeStudent` порог равен `1e-9`, то есть прогул разрешён только при
вероятности вопроса, равной нулю с точностью до погрешности `double`. Индукция:

1. В день 0 вектор `q` известен точно (все `false`);
2. Если прогуляли предмет, то `p ≈ 0`, значит `q = false` — тоже точно;
3. Если были на паре, `q` наблюдаем;
4. Значит `q` всегда точен → posterior точен → условие прогула не срабатывает
   ошибочно → вылетов нет.

Плата за это — невозможность отличить «Random, которому просто везло молчать»
от детерминированного правила, пока не наберётся достаточно наблюдений.
Отсюда разрыв ~290 против ~346.

## Как добавить свою стратегию

1. Создайте класс в `Strategy/`, реализующий `ISkipStrategy`:

   ```csharp
   public sealed class MyStrategy : ISkipStrategy
   {
       public string Name => "MyStrategy";

       public bool[] DecideDay(int day, IReadOnlyStudentHistory history)
       {
           var decisions = new bool[Constants.SubjectsCount];
           // true = идти на пару, false = прогулять
           return decisions;
       }
   }
   ```

2. Зарегистрируйте его в `Runner/Services/StrategyFactory.cs`: добавьте ветку
   в `switch` и имя в `Names` (оно попадёт в `--help`).

3. Проверьте:

   ```powershell
   dotnet run -- --batch --seed 12345 --strategy MyStrategy
   ```

### Важно про переиспользование экземпляра

В batch-режиме **один и тот же экземпляр** стратегии играет все 1000 семестров.
Если стратегия хранит состояние, она обязана сбрасывать его при `day == 0`.
Именно так делают обе байесовские стратегии.

## Известные ограничения

- **Стратегия не видит удовольствие и вылет.** История отдаёт только `Attended`
  и `WasAsked`, поэтому байесовские стратегии ведут оценку ожидаемого
  удовольствия самостоятельно.
- **`BayesOptimal` иногда вылетает** (в среднем ~1 раз за 100 дней). Для live-режима
  без обрыва используйте `BayesSafe`.
- **`RandomSkip` использует собственный `Random`**, а не `IRandomSource`. Это стоит
  перевести на `IRandomSource` при переходе к детерминированным тестам.
- **`--seed` действует только в batch.** Live-режим всегда стартует со случайным seed.
